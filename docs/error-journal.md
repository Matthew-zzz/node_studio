# Журнал ошибок

В кабинете администратора откройте «Ошибки». Сервер автоматически записывает неуспешные API-запросы, ошибки внешних сервисов (включая синхронизацию GitHub в успешном ответе snapshot), фоновых задач, резервных ответов ИИ, смыслового поиска и загрузки статических ресурсов. Неавторизованные пользователи, клиенты, разработчики и разработчики не имеют доступа к журналу. Все изменения требуют CSRF и актуальной роли администратора.

Запись содержит имя, почту, роль и ID пользователя из серверной сессии, связанный проект, время, число повторений, действие, HTTP-статусы приложения и внешнего сервиса, код причины, понятное объяснение, рекомендацию и ID запроса. Для фоновых задач сохраняется инициатор; если его нет — клиент проекта либо пользователь Telegram. Неопределённый пользователь явно отмечается. Неожиданные ошибки содержат только места вызовов в серверном коде, без текста исключения и содержимого запроса.

Поддерживаются поиск (включая кириллицу), фильтр сервиса, открытые и решённые ошибки, страницы по 30 записей. Повторения объединяются отдельно для каждого пользователя, проекта и операции. «Отметить решённой» меняет статус записи, но не устраняет причину. Следующий сбой после закрытия создаёт новую запись. Журнал обновляется каждые 10 секунд на открытой вкладке. В SQLite хранится до 2 000 записей; старые вытесняются. Данные сохраняются в существующем томе `portal-data` при обновлении Docker.

Сетевые сбои браузера, тайм-ауты, неожиданный формат ответа и HTTP-ошибки прокси без серверного ID ставятся в ограниченную очередь на устройстве (до 40 записей без содержимого запроса). После восстановления связи они отправляются в журнал. Повторы доставки дедуплицируются. Отчёт предыдущего профиля не записывается на имя другого аккаунта. Если личность до сбоя ещё не была определена, запись остаётся без атрибуции. При недоступности сервера мгновенная доставка невозможна; очистка хранилища браузера может удалить неотправленные сообщения. Время устройства в подробностях показывается отдельно от времени приёма сервером.

Тела и query-параметры запросов, пароли, ключи, заголовки авторизации, тексты переписки и произвольные тела ответов провайдеров не сохраняются. Внешние ошибки классифицируются по известным признакам: блокировка GitHub, права токена, лимиты, квота OpenAI, недоступность сервиса, неподтверждённый домен почты, блокировка Telegram-бота и ошибки HTML. Неизвестная причина явно остаётся неустановленной. Классификация не требует отправки диагностических данных ИИ.

После сбоя GitHub повторные синхронизации одного проекта используют паузу от 30 секунд до 5 минут и продолжают показывать последний кэш. Это не снимает ограничения провайдера. Если API сообщает `Your account was suspended`, восстановление выполняет владелец через [GitHub Appeal and Reinstatement](https://docs.github.com/en/site-policy/acceptable-use-policies/github-appeal-and-reinstatement). Ошибки прав и лимитов описаны в [Troubleshooting the REST API](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api).
