# ИИ-агент Telegram

Агент работает в [боте студии](https://t.me/node_studio_bot). Администратор управляет им из кабинета: «ИИ-агент», «Промпты», «База знаний», «Проверка агента» и «История настроек». Ключи OpenAI и Telegram остаются в конфигурации сервера, не возвращаются браузеру и не включаются в экспорт.

## Настройки и применение

Можно включить или приостановить автоматические ответы, изменить имя, модель, системный промпт, оформление, приветствие, ответы при передаче разработчику, ошибке и отсутствии знаний. Отдельно включаются консультации по базе знаний, сбор ТЗ, сбор почты и вызов разработчика. Разработчик по-прежнему может подключиться к переписке вручную; незавершённый ответ ИИ после подключения не отправляется.

В дополнительных настройках задаются размер истории, лимит токенов, длина ответа, число ответов в час на диалог, температура, усилие рассуждения и подробность. Дополнительные параметры по умолчанию не передаются провайдеру: совместимость выбранных значений зависит от модели. Модель должна поддерживать Responses API и Structured Outputs.

Кнопка «Сохранить настройки» применяет изменения без перезапуска Docker. Проверка использует текущую форму, в том числе несохранённые изменения, и не отправляет сообщения в Telegram, не создаёт диалоги, задачи или платежи. Если другую версию уже сохранили в соседней вкладке, сервер отклонит устаревшую запись. Обновление данных не стирает редактируемую форму. После отмены изменений форма получает последнюю версию с сервера.

Сохранённые версии можно восстановить; восстановление создаёт новую версию. Экспорт JSON содержит настройки и материалы. Импорт JSON загружает параметры в форму перед сохранением; материалы импортируются отдельно.

## База знаний и RAG

Материалы добавляются текстом либо из UTF-8 файлов TXT, MD, CSV и JSON до 200 КБ. В одном материале допускается до 50 000 символов; в базе — до 200 материалов и 2 млн символов, включая архив. Материалы можно редактировать, выключать, архивировать и возвращать в базу. Выключенные и архивные материалы не используются в ответах. PDF, DOCX, изображения и автоматическое чтение сайтов этим импортом не обрабатываются.

Поиск по словам использует локальный BM25 по фрагментам и названиям материалов. В гибридном режиме дополнительно строятся embeddings через OpenAI и сравниваются по косинусному сходству. Модель embeddings, размер фрагмента, перекрытие, число результатов, смысловой порог и общий размер контекста настраиваются. Изменения структуры индекса запускают его обновление через постоянную очередь SQLite. До готовности смыслового индекса и при его недоступности используется поиск по словам; это видно в проверке ответа.

В строгом режиме отсутствие подходящих фрагментов возвращает заданное сообщение без обращения к модели. Проверка показывает фактически выбранные фрагменты, HTML, модель и время ответа. Режим без строгого ограничения позволяет агенту уточнять вопрос и помогать по системному промпту. База знаний общая для Telegram-бота: добавленные сведения предназначены для его пользователей. Переписка других людей, клиентские GitHub-репозитории и ключи не добавляются к контексту.

## Telegram и надёжность

Ответы отправляются с `parse_mode: HTML`. Поддерживаются жирное и курсивное выделение, подчёркивание, зачёркивание, код, цитаты и безопасные ссылки. Сервер приводит HTML к ограниченному набору тегов, экранирует неподдерживаемую разметку, закрывает теги и ограничивает текст без обрыва Unicode. При ошибке разбора entities отправляется экранированный текст. В кабинете разработчика и проверке форматирование отображается через React-элементы, без вставки произвольного HTML в DOM.

Входящие Telegram-события и исходящие ответы проходят через постоянную очередь; повтор одного входящего события не создаёт новый ответ. При отключении агента, превышении лимита или ошибке генерации пользователь получает резервное сообщение, а диалог помечается для разработчика. Изменение промпта или материалов во время генерации отменяет устаревший результат и запускает ответ с актуальным контекстом. Журнал администратора содержит результат, модель, длительность и идентификаторы источников без текста переписки.

Данные сохраняются в `portal-data`: настройки, версии, материалы, фрагменты, embeddings и журнал. Обновление приложения не удаляет существующие аккаунты, сессии и диалоги.

Документация протоколов: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [embeddings](https://developers.openai.com/api/docs/guides/embeddings), [Telegram HTML](https://core.telegram.org/bots/api#html-style).
