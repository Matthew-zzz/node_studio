# Вход, сессии и восстановление

Вход выполняется по почте, паролю и роли существующего аккаунта. Выбор роли не создаёт аккаунт и не выдаёт права. При общей почте и общем пароле один подтверждённый вход добавляет в группу только существующие профили с тем же сохранённым паролем. У каждого профиля остаются собственные ID, роль и серверные проверки доступа к проектам.

После проверки пароля сервер отправляет шестизначный код. До его подтверждения нет авторизованной сессии, CSRF-токена или доступа к данным. Код действует 10 минут, используется один раз и привязан к отдельной HttpOnly cookie браузера. В базе хранится HMAC кода. Повторная отправка доступна через минуту; она не обнуляет число попыток. На код допускается пять попыток, также действуют общие ограничения по почте и IP. При недоступной почте вход закрыт, обхода по одному паролю нет.

Сессия длится 12 часов с момента входа. Серверный срок и Max-Age cookie согласованы; опрос данных и переключение ролей не продлевают срок. Обновление страницы, открытие соседней вкладки, повторный запуск браузера до истечения cookie и пересоздание контейнера сохраняют подтверждение. После истечения cookie, серверной сессии или выхода требуются пароль и новый код. В HTTPS используются HttpOnly, Secure, SameSite=Lax и host-only cookie с префиксом __Host-. Фронтенд не хранит пароли, коды и сессионные токены в localStorage. Переключение профиля обновляет токен и CSRF; привязка устройств хранится на сервере.

Успешное подтверждение новой сессии сохраняет уведомление о входе в постоянную очередь. Письмо содержит время по Москве, выбранный профиль, IP и устройство. Ссылка «Если это были не вы» действует 24 часа. Восстановление со страницы входа использует ссылку на 30 минут. Ответ на запрос восстановления одинаков для существующей и неизвестной почты; отправка происходит в фоне. Ссылки строятся из настроенного PORTAL_ORIGIN, а не заголовка Host запроса.

Страница `/recover/#<token>` не индексируется; токен из фрагмента не попадает в HTTP URL или Referer. Просмотр страницы и проверка ссылки не меняют пароль и не завершают сессии, поэтому почтовый сканер ссылок не выполняет операцию за пользователя. После ввода нового пароля сервер одной транзакцией обновляет пароль всех профилей на почте, отзывает их сеансы на всех устройствах, отменяет ожидающие коды и ссылки восстановления. Повторно использовать ссылку нельзя. Автоматического входа после сброса нет: снова требуются пароль и почтовый код. При обычной смене пароля в настройках сохраняется текущая группа устройства, остальные группы отзываются.

Коды и ссылки не выдаются в JSON, журнале ошибок или логах. В очереди письма со ссылками зашифрованы AES-256-GCM постоянным ключом из тома данных. Идемпотентный ключ Resend ограничивает повторы доставки. Просроченные подтверждения, ссылки, сессии и ограничения периодически удаляются. Новая версия требует почтового подтверждения для старых сессий, которые ещё не проходили этот шаг.

## Настройка аккаунтов владельца

Перед изменением сохраните резервную копию SQLite. Явная операторская команда:

```bash
docker compose exec -T app node server/cli.ts configure-owner <<'JSON'
{"email":"owner@example.ru"}
JSON
```

Команда предназначена для установки с одним клиентом и одним аккаунтом каждой служебной роли. Она проверяет состав аккаунтов, сохраняет их ID и проекты, назначает общую почту и существующий пароль клиента всем трём профилям. Все старые сеансы отзываются, на почту ставится в очередь ссылка восстановления. Если клиента ещё нет, создаётся настоящий профиль с временным случайным паролем; задать собственный пароль можно по ссылке. Несколько аккаунтов одной роли команда не объединяет автоматически. Старые первоначальные пароли сотрудников после переноса не действуют. Повторно запускать команду при каждом старте контейнера не требуется.

Почта для входа обязательна: PORTAL_RESEND_KEY, подтверждённый PORTAL_MAIL_FROM и постоянный PORTAL_ENCRYPTION_KEY. Последний обычно загружается приложением из защищённого runtime-secrets.json в томе. Отдельного режима отключения подтверждения для production нет. Автоматические проверки используют почтовый адаптер только в изолированных тестах.

При реализации учтены рекомендации [OWASP по восстановлению паролей](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) и [управлению сессиями](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
