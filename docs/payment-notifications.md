# Уведомления об оплате

При подготовке заказа куратором клиент автоматически получает ссылку `/checkout/#<token>` на указанную почту и в свой диалог с ботом. После успешного серверного подтверждения оплаты оба канала получают сообщение «Оплата прошла успешно» с названием проекта и оплаченной суммой. Создание оценки пожелания также уведомляет клиента: оплатить её можно в разделе «Чат» соответствующего проекта в кабинете. Цена пожелания включает наценку 30%.

Тестовая заглушка сохранена. Все уведомления явно сообщают, что деньги не списываются. Ошибка или отмена оплаты не создают подтверждение успеха. Отправка платёжных уведомлений не выдаёт доступ и не переводит проект в готовое состояние: существующая выдача доступа куратором остаётся отдельным действием.

`server/payment-notifications.ts` сохраняет событие и два независимых задания `payment.notify.mail` / `payment.notify.telegram` в одной SQLite-транзакции с изменением заказа или оценки. Повторное подтверждение не создаёт новое событие, включая повтор после выполнения заданий или перезапуска. Задания содержат идентификаторы, а не платёжный токен или ТЗ. Письма используют стабильный ключ идемпотентности Resend. Telegram не предоставляет ключ идемпотентности для `sendMessage`: при неопределённом сетевом результате доставки повторное сообщение технически возможно.

Клиент должен начать личный диалог с `@node_studio_bot`. Для заказа диалог определяется по указанному куратором username или единственной совпадающей почте; конфликтующие и неоднозначные контакты не используются. Для пожелания учитывается привязанный куратором бриф и контакт исходного заказа. Найденный числовой Telegram chat ID сохраняется: смена username не перенаправляет уведомление об успехе другому человеку. Доставленные сообщения видны в истории диалога у куратора; сами по себе они не запускают ИИ и не меняют владельца диалога.

Если один канал недоступен, другой продолжает работать. Задания переживают обновление контейнера, используют общую политику восьми попыток с задержкой и фиксируют сбои в разделе ошибок администратора с контекстом заказа или проекта. Отсутствие диалога с ботом также отражается там. После исчерпания попыток автоматическая отправка прекращается. При уже оплаченной или заменённой оценке неотправленное приглашение оплатить её отменяется. События создаются для новых операций; старые заказы не рассылаются при обновлении приложения.

Проверка: `npm run test:payments`. Тесты используют подставные почтовый и Telegram-адаптеры и не отправляют реальные сообщения.
