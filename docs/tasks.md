# Задачи из переписки

ИИ автоматически выделяет конкретные пожелания клиента в отдельные предложения.
Анализ запускается после сообщения клиента в чате проекта и в Telegram-диалоге,
который разработчик явно связал с проектом через бриф. При открытии проекта
анализируется ещё не обработанная переписка. Анализ продолжается при подключённом
разработчике и не отправляет ответы от его имени.

Карточки видны в чате, обзоре и разделе «Задачи». Клиент может отдельно одобрить,
отклонить или уточнить формулировку. До одобрения это локальное предложение;
GitHub не изменяется. Подготовка репозитория не требуется для обсуждения,
уточнения и отклонения предложений.

## Уточнение и отмена

- Новое независимое пожелание создаёт отдельную карточку.
- Уточнение несогласованного пожелания меняет ту же карточку и её версию.
- Явный отказ от несогласованного пожелания отзывает карточку, сохраняя историю.
- Правка согласованной задачи создаёт предложение изменений с прежним и новым
  описанием. После одобрения обновляется та же GitHub Issue.
- Отмена согласованной задачи сначала предлагается клиенту; после одобрения
  Issue закрывается со статусом отмены. Отклонение такого предложения сохраняет
  исходную задачу.
- Если клиент хочет вернуть уже отменённую задачу, предлагается её возобновление;
  после нового одобрения открывается та же Issue.
- В каждый момент у существующей задачи может быть одно актуальное предложение
  изменений или отмены. Более поздние уточнения обновляют его.

ИИ получает текущие предложения, прошлые решения, задачи, бриф и последние
сообщения только этого проекта. Слова разработчика и ИИ не заменяют согласие
клиента. Для изменения обязательно указываются реальные сообщения клиента;
неизвестные идентификаторы, чужие проекты, несколько изменений одной карточки
в одном ответе и некорректные ответы отклоняются одной транзакцией.

Клиентское решение проверяет владельца, CSRF и номер версии. Устаревшее
одобрение не применяется. Если во время анализа пришло новое сообщение или
изменилось решение клиента, прежний результат не записывается. Ручная
формулировка клиента имеет приоритет над предыдущими сообщениями.

## GitHub и стоимость

Предложения могут относиться к разным подпроектам; ИИ выбирает источник по
доступным названиям. Изменение существующей задачи сохраняет её источник.
Старые черновики по умолчанию относятся к основному репозиторию.

Создание Issue использует постоянный маркер черновика: повтор после потери
ответа GitHub не создаёт дубль. При изменении проверяется прежнее описание;
если разработчик уже изменил его на GitHub, требуется новое согласование.
Синхронизация и одобрение защищены общими блокировками проекта и источников.

После одобренного изменения пожелания начинается новая версия объёма работ:
статус возвращается в «Не начато», включение в ТЗ снимается, ожидающие оценки
становятся устаревшими. Разработчик заново включает задачу в ТЗ или выставляет
оценку. Прежние платежи сохраняются в истории и не оплачивают автоматически
новые требования. Отмена не выполняет автоматического возврата денег.

Общее первоначальное ТЗ не переписывается этим агентом: дополнения к нему
оформляются отдельными пожеланиями. Этапы проекта остаются отдельными Issues.

## Надёжность и данные

Очередь `tasks.analyze`, предложения `drafts`, история `draftRevisions`, состояние
`taskAnalysis` и версии оплачиваемого объёма `taskScopes` хранятся в SQLite.
Состояние анализа и задание фиксируются одной транзакцией. Если задание было
потеряно в старом состоянии данных, открытие проекта восстанавливает очередь.
Новая схема таблиц не нужна; старые черновики и платежи совместимы.
Интерфейс показывает последние 20 версий карточки, полная история остаётся в БД.

Анализ имеет отдельный последовательный исполнитель и не блокирует отправку
писем, обычные ответы и остальные фоновые операции. Новые сообщения объединяют
ожидающие задания диалога; неактуальный результат пропускается. Контекст
ограничен последними 80 сообщениями и бюджетами текста для переписки, текущих
предложений и задач. После ошибки выполняется до восьми попыток с паузой;
доступен ручной повтор через «Обновить задачи из переписки».

Проверки: `npm run test:tasks`, `npm run check`, `npm run test:e2e`.
Адаптеры ИИ и GitHub в тестах изолированы: реальные репозитории и сообщения
пользователей не изменяются.
