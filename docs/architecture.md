# Архитектура и развитие

## Ответственность каталогов

`app` связывает маршруты с функциональностью и содержит инфраструктуру Next.js: корневой layout, метаданные, sitemap, robots, страницы ошибки и 404. В маршрутах нет данных проектов и HTML-шаблонов в строках.

`features` группирует код по предметной области. `home` содержит композицию главной страницы; `projects` отвечает за кейсы и их изображения; `services` — за описания услуг и иллюстрации. Внутри каждой области добавляются только используемые каталоги: `components`, `data`, `model`, `lib`, `styles`.

`components/ui` содержит общие визуальные и интерактивные элементы. `components/layout` — каркас сайта. `components/sections` — секции, которые используются на нескольких страницах. Общие компоненты не импортируют страницы и данные конкретных кейсов.

`config` хранит контакт, описание студии и навигацию. `lib` содержит небольшие общие функции. Локальные функции остаются рядом с компонентом, пока не появляются реальные повторные использования.

## Зависимости и типы

- Импорты между модулями приложения идут через `@/`. Соседний CSS Module импортируется через `./`. Используйте прямой импорт нужного файла: общие barrel-файлы не требуются.
- Маршруты и составные страницы могут собирать компоненты нескольких features. Не создавайте циклические зависимости и импорт из `app` в features или UI.
- Модели описывают данные, компоненты — представление. Не храните HTML-строки в контенте. Для форматированного текста используйте JSX и `ReactNode`.
- Включены `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`. Не подменяйте неизвестное значение типом `any` или необоснованным утверждением типа.
- Данные readonly. Объекты галереи имеют именованные поля; для поиска проекта используются функции из `features/projects/lib/projects.ts`.
- Не добавляйте API-клиент, глобальное состояние или каталоги-заглушки до появления сценария, которому они нужны.

Эти границы проверяет ESLint: `components`, `lib` и `config` не могут импортировать `features` и `app`; функциональные модули не могут зависеть от `app`. Относительные переходы через `../` внутри приложения также запрещены.

## Сервер и браузер

По умолчанию компоненты серверные. `"use client"` стоит только у компонентов, которым нужны состояние, обработчики событий или браузерные API: меню, копирование контакта, активация анимаций и эффекты страницы. Серверный JSX можно передать клиентскому компоненту через `children`.

Используйте React для изменения содержимого и состояния интерфейса. Прямые изменения DOM ограничены измерением SVG-линий, CSS-свойствами и декоративными анимациями. Все наблюдатели, обработчики и таймеры освобождаются при размонтировании. `SiteEffects` обновляет наблюдения при изменении маршрута.

Движение останавливается вне экрана, на скрытой вкладке и при `prefers-reduced-motion`. Содержимое остаётся доступно без анимации. FAQ и услуги используют нативные `details`/`summary`; меню — `dialog`, который обеспечивает модальность и удержание фокуса. Кнопка меню отражает состояние через `aria-expanded`.

`observeMotion` отдельно сообщает активность и пользовательское предпочтение уменьшения движения. Временная пауза при прокрутке не должна переключать разметку или менять высоту блока. Управление первым экраном и бегущими строками лежит в `features/home`, геометрией иллюстраций — в `features/services`; общие UI-компоненты не знают о селекторах конкретных секций.

## Как добавить кейс

1. Поместите изображения в `public/assets/`. Не используйте `dist` как источник материалов.
2. Зарегистрируйте настольный и при наличии мобильный вариант в `features/projects/data/screenshots.ts`, указав реальные размеры.
3. Добавьте объект `Project` в `features/projects/data/projects.ts` с уникальным `slug`, описанием задачи, решения, результата и галереей.
4. При необходимости задайте заголовок галереи в `project-gallery.tsx`.
5. Обновите ожидания маршрутов в `tests/export.test.mjs`, затем выполните build и проверки.

Главная, статические параметры маршрута и sitemap используют один список `projects`. Новый маршрут создаётся при следующей сборке. Для неизвестного slug показывается 404.

## Как добавить секцию или услугу

Новую независимую секцию главной помещайте в `features/home/components`; повторно используемую секцию — в `components/sections`. Подключайте её явно в `home-page.tsx`.

Для услуги добавьте данные в `features/services/data/services.ts`. Мобильный список строится из `serviceOfferings`, настольные истории — из `clientSituations`. Если меняется набор историй, обновите тип `SituationId` и таблицу иллюстраций: TypeScript проверит соответствие.

## Стили

Общие цвета и шрифты находятся в `styles/tokens.css`, базовые правила — в `styles/base.css`. Стили услуг, кейсов и главной лежат рядом с соответствующей feature. Адаптивные правила прежнего сайта сохранены в `styles/responsive*.css`; их порядок в `app/layout.tsx` сохраняет исходный каскад.

Существующие глобальные классы оставлены для совместимости дизайна. Для новых изолированных компонентов используйте `*.module.css` рядом с компонентом. Не наращивайте общий файл повторными переопределениями; изменяйте правило в ответственном модуле. Перенос старых глобальных правил в CSS Modules следует делать по компонентам с визуальной проверкой.

Бегущие строки уже используют `features/home/components/marquee.module.css`. Все их состояния и мобильные правила, включая отступ до услуг, принадлежат этому модулю и не переопределяются в общих адаптивных файлах.

## Проверки и зависимости

Версии зависимостей закреплены вместе с `package-lock.json`; установка — `npm ci`. ESLint проверяет рекомендации Next.js/React, типовые импорты и оформление JSX. TypeScript проверяется отдельно от lint и также при production-сборке. Не отключайте эти проверки для прохождения CI.

Тесты экспорта разбирают итоговый HTML через parse5 и проверяют маршруты, метаданные, ссылки, якоря, ARIA, размеры изображений, анонимизацию поставщиков, переход к следующему кейсу, sitemap и сохранность ресурсов. Браузерный сценарий проверяет размеры 320, 390, 768 и 1440 px, отсутствие горизонтального переполнения, меню и фокус, аккордеоны, навигацию после гидратации и копирование. Отдельный сценарий в `tests/browser/motion.mjs` проверяет, что пауза вне экрана сохраняет высоту бегущей строки, а переключение `prefers-reduced-motion` показывает полный статичный список и позволяет затем возобновить анимацию.

Источники соглашений: [Next.js App Router](https://nextjs.org/docs/app), [структура проекта](https://nextjs.org/docs/app/getting-started/project-structure), [статический экспорт](https://nextjs.org/docs/app/guides/static-exports).
