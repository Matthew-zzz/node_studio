# Плавность карусели AnimeLove — 30 октября 2026

Исправлена отрисовка `/projects/anime-love/` относительно ревизии `4196d1b`. Исходный аудит скорости загрузки не выявлял масштаб проблемы: рывки возникали при прокрутке к 3D-галерее.

## Причина и изменение

На каждом экране сочетались большие размытые тени, фильтры насыщенности/яркости, вложенные 3D-сцены и постоянный `will-change`. Дополнительно фон имел размытие 70 px. Скрытый четвёртый экран сохранял отдельный слой. Такая композиция дорого обходилась отрисовке, хотя JavaScript прокрутки почти не занимал процессор.

Фильтры экранов удалены, фоновое свечение заменено радиальным градиентом. Тени уменьшены и больше не анимируются. Перспектива и положения карточек сохранены; каждый экран представляет собой одну плоскую поверхность. Дальний невидимый экран получает `visibility: hidden` после завершения ухода, а область галереи с заданной высотой использует `content-visibility: auto`. В браузерах без этой возможности сохраняется обычная отрисовка.

Наклон от курсора обновляет только активную карточку, максимум один раз за кадр. Размеры области кешируются, при прокрутке/изменении размера кеш и наклон сбрасываются. Отложенный кадр отменяется при уходе курсора, скрытии вкладки и удалении компонента. На сенсорных устройствах и при reduced motion наклон отключён.

## Измерения

Последовательные headless Chromium проверки на одном VPS, после завершения загрузки страницы. Базовая версия открывалась на опубликованном сайте, исправленная — на локальном сервере той же production-сборки. Это лабораторные измерения; физические устройства не подключены.

| Сценарий | До: p95 между кадрами | После: p95 между кадрами |
| --- | ---: | ---: |
| 1440 × 1000, DPR 1, программная прокрутка через галерею и обратно | 50,0 мс | 16,8 мс |
| 1920 × 1080, DPR 2, события колеса через CDP | 66,7 мс | 33,4 мс |
| Профиль Pixel 7, CPU ×6, программная прокрутка | 16,8 мс | 16,7 мс |

В первом сценарии количество интервалов длиннее 34 мс снизилось с 53 из 209 до 1 из 376. Во втором — с 64 из 173 до 5 из 295. Замедленный мобильный профиль уже проходил этот сценарий прокрутки плавно; улучшение там по этим кадрам не установлено. В единичной последовательности переключений INP снизился со 120 до 56 мс на компьютере и с 216 до 128 мс на CPU ×6; эти значения не являются пользовательским p75 и требуют повторов для статистических выводов.

Отдельный полный сценарий `audit:browser` с открытием меню и всеми переключениями также завершён в компьютерном и CPU ×6/4G профилях, CLS 0, без ошибок JS/HTTP. Он дал p95 прокрутки 33,3 и 16,8 мс соответственно. Общий INP составил 104 и 352 мс: на замедленном профиле самым долгим действием было меню. Эта правка не устраняет ранее найденную задержку меню и не даёт основания объявлять все взаимодействия быстрыми.

Числа и события трассировки: [2026-10-30-carousel-results.json](2026-10-30-carousel-results.json). Полные трассы, сравнительные скриншоты и диагностические сценарии сохранены локально в `.cache/carousel-performance/`.

## Проверки

- Production-сборка, TypeScript, ESLint, 19 проверок экспорта и HTTP.
- Все изображения, управление каруселью и отсутствие переполнения на 320, 390, 760, 768, 1024, 1440 и 1920 px, DPR 1–3.
- Свайп, перетягивание мышью, стрелки, клавиатура, смена ориентации и PNG/JPEG fallback без JavaScript.
- Автоперелистывание: пауза вне экрана, в скрытой вкладке, при фокусе/наведении и reduced motion; возобновление без пропуска экранов и дублирования таймеров.
- Быстрые входы/выходы курсора и девять последовательных переключений при DPR 2: видимый декодированный экран, без ошибок JavaScript.
- Linux WebKit с профилем iPhone 13: все четыре экрана переключились без падения процесса в scope с лимитом памяти 900 МБ. Это проверка движка, не подтверждение производительности физического iPhone.

В `scripts/audit-browser.mjs` добавлен повторяемый проход через карусель. Подготовка инструментов описана в исходном [аудите](2026-10-30.md). Запуск отдельно от сборок и других браузеров:

```bash
AUDIT_PROFILES=desktop-chromium,android-slow4g-cpu6 \
AUDIT_ROUTES=/projects/anime-love/ \
AUDIT_OUTPUT_DIR=.cache/performance-audit/carousel \
npm run audit:browser
```

`AUDIT_ORIGIN` позволяет проверить локальную production-сборку. Показатели нового сценария находятся в `runs[].steps[]`: `carouselScrollFrames`, `frameMedianMs`, `frameP95Ms`, `framesOver34Ms` и `framesOver50Ms`.
