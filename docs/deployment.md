# Размещение публичного сайта

Сайт экспортируется Next.js в статические файлы и отдаётся небольшим Node.js сервером внутри Docker-контейнера. Приложение не запускает API и не использует базу данных.

## Запуск и обновление

Из checkout проекта:

```bash
SOURCE_REVISION="$(git rev-parse HEAD)" docker compose up -d --build --wait
docker compose ps
```

Контейнер доступен через `127.0.0.1:3158`. Внешний Nginx продолжает завершать HTTPS и проксирует запросы на этот адрес. Порты и адрес привязки можно изменить через `HTTP_PORT` и `BIND_ADDRESS` в локальном `.env`.

## Старые данные панели

Именованный том `portal-data` оставлен отсоединённым от контейнера. Новая версия сайта его не читает и не меняет. Не используйте `docker compose down -v`, пока владелец отдельно не подтвердит удаление старых данных.

После подтверждения том можно удалить отдельной операцией. В нём хранятся записи старой панели, включая аккаунты, проекты, задачи, переписки и настройки.

## Проверка

```bash
docker compose ps
curl --fail https://node-studio.ru/
```

Контейнер должен показывать состояние `healthy`. Healthcheck обращается к главной странице внутри контейнера.

Сборка поддерживает BuildKit secret `proxy_ca`, если в окружении требуется доверенный сертификат прокси. Не отключайте TLS-проверку.
