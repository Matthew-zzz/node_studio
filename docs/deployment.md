# Размещение публичного сайта

Сайт экспортируется Next.js в статические файлы и отдаётся небольшим Node.js сервером внутри Docker-контейнера. Приложение не запускает API и не использует базу данных.

## Запуск и обновление

Из checkout проекта:

```bash
SOURCE_REVISION="$(git rev-parse HEAD)" docker compose up -d --build --wait
docker compose ps
```

Контейнер доступен через `127.0.0.1:3158`. Внешний Nginx продолжает завершать HTTPS и проксирует запросы на этот адрес. Порты и адрес привязки можно изменить через `HTTP_PORT` и `BIND_ADDRESS` в локальном `.env`.

## Старые данные панели

Именованный том `portal-data` оставлен отсоединённым от контейнера. Новая версия сайта его не читает и не меняет. Не используйте `docker compose down -v`, пока владелец отдельно не подтвердит удаление старых данных.

После подтверждения том можно удалить отдельной операцией. В нём хранятся записи старой панели, включая аккаунты, проекты, задачи, переписки и настройки.

## Проверка

```bash
docker compose ps
curl --fail https://node-studio.ru/
```

Контейнер должен показывать состояние `healthy`. Healthcheck обращается к главной странице внутри контейнера.

## Gzip

При `npm run build` финализация экспорта создаёт `.gz` рядом с HTML, CSS, JS, JSON, TXT, XML и SVG размером от 1 КБ, если сжатие уменьшает файл. Используется встроенный Gzip Node.js, уровень 9. Исходники сохраняются. Видео, WebP, JPEG, PNG и шрифты повторно не сжимаются.

Приложение отдаёт готовую версию при поддержке `gzip` клиентом. При отсутствии, недоступности или устаревании `.gz` возвращается исходный файл. Новые модули Nginx и сжатие во время запросов не требуются. `Vary: Accept-Encoding` и отдельные ETag разделяют варианты в кеше; MIME-тип остаётся исходным. Запросы диапазона байтов используют оригинал, сохраняя перемотку видео. Явный запрет клиентом всех доступных кодировок обрабатывается ответом 406.

В конфигурации HTTPS-сервера Nginx должно быть `gzip off;`, как в `deploy/nginx.conf`: это исключает повторное сжатие и сохраняет выдачу оригинала при отсутствии `.gz`.

HTTP-проверки запускаются вместе с `npm test`. Они сравнивают распакованный ответ с оригиналом и проверяют fallback, согласование кодировки, HEAD, ETag/304 и диапазоны байтов. Для ручной проверки:

```bash
curl -I -H 'Accept-Encoding: gzip' https://node-studio.ru/
curl -I -H 'Accept-Encoding: identity' https://node-studio.ru/
```

Сжатый ответ содержит `Content-Encoding: gzip`, обычный — нет. Оба варианта HTML имеют `Vary: Accept-Encoding`.

Сборка поддерживает BuildKit secret `proxy_ca`, если в окружении требуется доверенный сертификат прокси. Не отключайте TLS-проверку.
