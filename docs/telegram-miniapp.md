# Telegram Mini App

Кабинет внутри Telegram доступен по `/miniapp/`. Оплата первоначального заказа — `/miniapp/checkout/#<token>`, восстановление — `/miniapp/recover/#<token>`. Страницы исключены из индексации и sitemap. Сайт `/cabinet/` продолжает работать.

## Общая логика

Mini App использует `Portal`, `usePortal`, существующие компоненты проектов, чатов, заказов и администрирования и тот же сервер `/api/portal/`. Роли, оплата, подтверждение задач, GitHub и очередь создания репозитория не продублированы. `model/navigation.ts` задаёт общие названия и доступные разделы; `features/telegram` отвечает за мобильную оболочку и Telegram SDK.

Клиент начинает со списка проектов, разработчик — со списка Telegram-диалогов. Внутри проекта нижняя панель открывает обзор, задачи, историю и чат. В Mini App рабочая область показывает один раздел; кнопка «Открыть рядом» доступна в веб-кабинете. У разработчика из списка и меню доступна общая очередь; подпроект выбирается в рабочей области. Нижняя навигация разработчика открывает проекты в работе, диалоги, общую очередь и создание проектов. В меню «Ещё» сразу под почтой расположен блок «Сменить профиль»: разработчик и администратор могут подтвердить вход в другую существующую роль и затем переключаться в течение сессии без выхода. Клиентские профили не получают доступ к ролям сотрудников. В «Диалогах» сначала отображается полный список с поиском и фильтрами. Нажатие открывает отдельный экран переписки; список и нижняя навигация скрываются, имя клиента и кнопка возврата находятся в шапке. «Итоговый бриф» доступен внутри диалога. Экранная и нативная кнопки «Назад» возвращают к списку с прежними поиском, фильтром и позицией прокрутки. Черновики сообщений сохраняются между переходами по диалогам в текущем разделе, отдельно для каждого клиента; возврат к списку не отключает разработчика от диалога. У администратора доступны агент, знания, ошибки, а дополнительные настройки — через «Ещё». Профили, тема, безопасность аккаунта и поддержка находятся в компактном меню.

Оболочка ограничена шириной 560 px, включая Telegram Desktop. Основной экран прокручивается внутри приложения; нижняя навигация остаётся в видимой области. Поля имеют размер шрифта 16 px, действия — области нажатия от 44 px. Отступы учитывают вырезы устройства и элементы Telegram. Высота обновляется по стабильному viewport Telegram и VisualViewport браузера; при небольшой высоте и фокусе на поле навигация скрывается, освобождая место клавиатуре. Длинные тексты раскрываются существующими компонентами.

SDK загружается только для `/miniapp/`. Используются `ready`, `expand`, `BackButton`, тема, безопасные отступы и открытие внешних ссылок. Явный выбор темы пользователя имеет приоритет над темой Telegram. Обработчики снимаются при размонтировании; без Telegram SDK остаётся рабочий мобильный кабинет. Контракт SDK — в [документации Telegram](https://core.telegram.org/bots/webapps).

## Авторизация

Вход использует почту и одноразовый код из письма. Новая сессия внутри Telegram сохраняется до 30 дней с момента подтверждения; браузерные сессии действуют 12 часов. Уведомления о входе и восстановление с отзывом всех сеансов сохраняются. Telegram ID, username, `initDataUnsafe` и параметры URL не дают доступа к аккаунтам. Подписанный запуск используется для изоляции сессий, а код из письма подтверждает первый вход.

Gateway передаёт `X-Portal-Client: miniapp` и подписанный `Telegram.WebApp.initData`. До загрузки SDK запросы к кабинету не выполняются. Сервер проверяет [HMAC по протоколу Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), `auth_date` (до 12 часов с допуском 60 секунд на расхождение часов) и положительный целочисленный ID. Повторяющиеся параметры, некорректные подписи и запуск другого бота отвергаются.

Каждому ID соответствует отдельная пара `__Host-node_miniapp_session_v2_<namespace>` / `__Host-node_miniapp_challenge_v2_<namespace>`. Namespace — HMAC от ID; он не содержит открытый Telegram ID или токен бота. Группа сессии хранит контекст в `auth_session_contexts`, одноразовый код — в `auth_challenges.context`. Даже ручное переименование cookie не переносит сессию или код в другой Telegram-профиль. Обновлённый подписанный запуск того же пользователя сохраняет его сессию; username не участвует в выборе аккаунта.

В HTTPS cookies имеют HttpOnly, Secure, SameSite=None, Partitioned, Path=/ без Domain; на локальном HTTP — SameSite=Lax. Обычный браузер `/miniapp/` явно передаёт `X-Telegram-Context: browser` и имеет собственный namespace `browser`, веб-кабинет — прежние cookies и SameSite=Lax. Запросы старого клиента без контекста отклоняются с предложением переоткрыть миниапп. Старые общие cookies Mini App больше не читаются, поэтому после первого обновления потребуется повторный код. Существующие веб-сессии сохраняются. Проверки роли, Origin и CSRF действуют во всех контекстах.

При смене контекста (возврат к приложению, фокус или смена подписанных данных) кабинет размонтируется: формы, открытые проекты и код предыдущего профиля не переносятся. Поздние ответы старого gateway отбрасываются. Каналы переключения профилей и очередь ошибок также разделены по контекстам. При отсутствии подписанных данных в нативном Telegram нет перехода к браузерной сессии. При сбое SDK предлагается повтор загрузки.

Выход завершает только текущую группу Telegram-профиля. Явное завершение всех сеансов по ссылке из уведомления или в настройках отзывает все связанные сеансы на почте, включая веб-кабинет и другие Telegram-профили. Подписанные данные не сохраняются в localStorage, URL, отчётах или ответах API.

Для сохранения входа после закрытия WebView используется [SecureStorage Telegram 9.0+](https://core.telegram.org/bots/webapps#securestorage). Ключ `node_login_v1_<telegram-identity>` хранит токен последней выбранной роли и абсолютный срок сессии. Токен заменяется после подтверждённого входа и переключения роли. Очередь записи не позволяет позднему ответу старого профиля заменить новые данные. При запуске gateway сначала читает защищённое хранилище; если cookie исчезла, сервер восстанавливает её по `X-Portal-Session` после проверки подписанного Telegram-контекста. Срок сессии не продлевается. Потеря cookie не требует нового письма, пока сохранённая серверная сессия действительна.

Сбой или отсутствие SecureStorage не блокирует вход через cookie и не вызывает запись токена в браузерное хранилище. Выход очищает локальный ключ и отзывает серверные сессии. Для истёкших и отозванных сессий требуется новый код; автоматического продления или назначения роли нет. Клиенты, вошедшие до обновления, сохраняют исходный срок сессии: 30 дней применяются после нового подтверждения по почте.

Для HTML Mini App сервер задаёт `frame-ancestors 'self' https://web.telegram.org https://*.web.telegram.org`. При настройке другого reverse proxy убедитесь, что его X-Frame-Options/CSP не запрещает Telegram Web.

## Кнопка бота

После публикации выполните операторскую команду с уже настроенным Telegram-токеном:

```bash
docker compose exec -T app node server/cli.ts telegram-menu < /dev/null
```

Команда проверяет бота через `getMe`, устанавливает меню «Кабинет» с HTTPS-адресом `/miniapp/` и проверяет результат через `getChatMenuButton`. Сообщения пользователям и изменения webhook не отправляются. Токен не печатается. Кнопка меню задаётся методом [setChatMenuButton](https://core.telegram.org/bots/api#setchatmenubutton); отдельная большая кнопка Main Mini App в профиле бота настраивается в BotFather.

## Проверки

`npm test` проверяет подписи Telegram, изоляцию Telegram-профилей и cookie-контекстов, обязательный почтовый код, права, Origin/CSRF и настройку меню без отправки сообщений. `npm run test:miniapp` проверяет три роли, создание проекта, очередь GitHub, чат, оценки, тестовую оплату, темы, кнопку «Назад», клавиатуру и отсутствие горизонтального переполнения при ширине 320, 390, 430 и 768 px. SDK, почта и GitHub заменены адаптерами только в тестах; production-обходов авторизации нет. Отдельный `tests/telegram-auth-browser.mjs` проверяет два Telegram-профиля с общей cookie-банкой, отложенный SDK, переключение без перезапуска, раздельные коды, поздний ответ и локальный выход. Полный `test:e2e` включает сайт и Mini App.

Подробности проекта, формы, настройки и диагностика открываются в общих диалогах с размытием фона. «Назад» сначала закрывает текущее окно и возвращает фокус на действие; список и чат под ним сохраняют своё состояние. [Поведение интерфейса](interface.md).
