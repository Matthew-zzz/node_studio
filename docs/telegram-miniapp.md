# Telegram Mini App

Кабинет внутри Telegram доступен по `/miniapp/`. Оплата первоначального заказа — `/miniapp/checkout/#<token>`, восстановление — `/miniapp/recover/#<token>`. Страницы исключены из индексации и sitemap. Сайт `/cabinet/` продолжает работать.

## Общая логика

Mini App использует `Portal`, `usePortal`, существующие компоненты проектов, чатов, заказов и администрирования и тот же сервер `/api/portal/`. Роли, оплата, подтверждение задач, GitHub и очередь создания репозитория не продублированы. `model/navigation.ts` задаёт общие названия и доступные разделы; `features/telegram` отвечает за мобильную оболочку и Telegram SDK.

Клиент начинает со списка проектов, разработчик — со списка Telegram-диалогов. Внутри проекта нижняя панель открывает обзор, задачи, историю и чат. В Mini App рабочая область показывает один раздел; кнопка «Открыть рядом» доступна в веб-кабинете. У разработчика из списка и меню доступна общая очередь; подпроект выбирается в рабочей области. Нижняя навигация разработчика открывает диалоги, общую очередь и создание проектов; принятые проекты доступны через меню. В «Диалогах» сначала отображается полный список с поиском и фильтрами. Нажатие открывает отдельный экран переписки; список и нижняя навигация скрываются, имя клиента и кнопка возврата находятся в шапке. «Итоговый бриф» доступен внутри диалога. Экранная и нативная кнопки «Назад» возвращают к списку с прежними поиском, фильтром и позицией прокрутки. Черновики сообщений сохраняются между переходами по диалогам в текущем разделе, отдельно для каждого клиента; возврат к списку не отключает разработчика от диалога. У администратора доступны агент, знания, ошибки, а дополнительные настройки — через «Ещё». Профили, тема, настройки пароля и поддержка находятся в компактном меню.

Оболочка ограничена шириной 560 px, включая Telegram Desktop. Основной экран прокручивается внутри приложения; нижняя навигация остаётся в видимой области. Поля имеют размер шрифта 16 px, действия — области нажатия от 44 px. Отступы учитывают вырезы устройства и элементы Telegram. Высота обновляется по стабильному viewport Telegram и VisualViewport браузера; при небольшой высоте и фокусе на поле навигация скрывается, освобождая место клавиатуре. Длинные тексты раскрываются существующими компонентами.

SDK загружается только для `/miniapp/`. Используются `ready`, `expand`, `BackButton`, тема, безопасные отступы и открытие внешних ссылок. Явный выбор темы пользователя имеет приоритет над темой Telegram. Обработчики снимаются при размонтировании; без Telegram SDK остаётся рабочий мобильный кабинет. Контракт SDK — в [документации Telegram](https://core.telegram.org/bots/webapps).

## Авторизация

Вход сохраняет пароль и одноразовый код из письма, абсолютную сессию 12 часов, уведомление о входе и восстановление с отзывом всех сеансов. Telegram ID, username, `initDataUnsafe` и параметры URL не дают доступа к аккаунтам. Автоматического входа по Telegram нет; сведения из SDK используются только для отображения.

Gateway передаёт `X-Portal-Client: miniapp`. Сервер использует отдельные cookies `__Host-node_miniapp_session` и `__Host-node_miniapp_challenge`. В HTTPS это HttpOnly, Secure, SameSite=None, Partitioned, Path=/ без Domain; это позволяет работать внутри Telegram Web с разделённым хранилищем cookies. На локальном HTTP остаётся SameSite=Lax. Веб-кабинет сохраняет прежние cookies и SameSite=Lax. Подробности разделённого хранилища — [CHIPS](https://developer.mozilla.org/en-US/docs/Web/Privacy/Guides/Third-party_cookies/Partitioned_cookies).

Выбор cookie-контекста не меняет проверку пароля, кода, роли, Origin или CSRF. Вход и выход в Mini App не переиспользуют сессию веб-кабинета. Восстановление пароля отзывает все связанные сеансы обоих интерфейсов. Очередь отчётов браузера также разделена; запросы ошибок используют тот же Mini App контекст.

Для HTML Mini App сервер задаёт `frame-ancestors 'self' https://web.telegram.org https://*.web.telegram.org`. При настройке другого reverse proxy убедитесь, что его X-Frame-Options/CSP не запрещает Telegram Web.

## Кнопка бота

После публикации выполните операторскую команду с уже настроенным Telegram-токеном:

```bash
docker compose exec -T app node server/cli.ts telegram-menu < /dev/null
```

Команда проверяет бота через `getMe`, устанавливает меню «Кабинет» с HTTPS-адресом `/miniapp/` и проверяет результат через `getChatMenuButton`. Сообщения пользователям и изменения webhook не отправляются. Токен не печатается. Кнопка меню задаётся методом [setChatMenuButton](https://core.telegram.org/bots/api#setchatmenubutton); отдельная большая кнопка Main Mini App в профиле бота настраивается в BotFather.

## Проверки

`npm test` проверяет изоляцию cookie-контекстов, обязательный почтовый код, права, Origin/CSRF и настройку меню без отправки сообщений. `npm run test:miniapp` проверяет три роли, создание проекта, очередь GitHub, чат, оценки, тестовую оплату, темы, кнопку «Назад», клавиатуру и отсутствие горизонтального переполнения при ширине 320, 390, 430 и 768 px. SDK, почта и GitHub заменены адаптерами только в тестах; production-обходов авторизации нет. Полный `test:e2e` включает сайт и Mini App.
