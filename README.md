# Node Studio

Сайт и личные кабинеты на Next.js, React и TypeScript. **Фронтенд и бэкенд запускаются в одном Docker-контейнере**: Node.js отдаёт собранные страницы и `/api/portal/` на одном порту. Данные кабинета сохраняются в Docker volume.

## Запуск

Нужны Docker Engine и Docker Compose 2.24+. Из корня репозитория:

```bash
docker compose up -d --build --wait
```

Контейнер доступен на `127.0.0.1:3158`. Для домена `https://node-studio.ru` используется существующий Nginx с конфигурацией [deploy/nginx.conf](deploy/nginx.conf). Для локального входа создайте `.env` из `.env.example` и задайте `PORTAL_ORIGIN=http://localhost:3158`.

При первом запуске создаются аккаунты разработчика, поддержки и администратора. Случайные временные пароли сохраняются в `/data/initial-access.json` внутри тома. Посмотреть их на своём сервере:

```bash
docker compose exec app node -e "process.stdout.write(require('node:fs').readFileSync('/data/initial-access.json','utf8'))"
```

Вход — `/cabinet/`. При первом входе пароль обязательно меняется. Аккаунты, переписка и платежи сохраняются в серверной базе при обновлении контейнера. GitHub, Telegram, ИИ и почта подключаются через `.env`. По решению владельца оплата пока работает через явно обозначенную серверную заглушку без списания денег.

Роль определяется серверной сессией. Клиент видит только свои проекты, этапы, задачи, историю и чат; разработчик берёт проекты из общей очереди; куратор работает с обращениями и подготовкой проектов. Администратор настраивает Telegram-агента: функции, модели, промпты, RAG, тестовые ответы и версии настроек. Инструкция — [docs/telegram-agent.md](docs/telegram-agent.md). Публичного переключателя ролей и автоматически заполненных клиентских проектов нет.

В разделе администратора «Ошибки» автоматически собираются сбои запросов, внешних сервисов и фоновых задач с пользователем, проектом, причиной и рекомендацией. Поддерживаются поиск, фильтры, счётчик повторений и история решения. Сетевые ошибки браузера доставляются после восстановления связи. Подробности — [docs/error-journal.md](docs/error-journal.md).

Разработчик может объединить несколько существующих GitHub-репозиториев в один клиентский проект. Клиент получает общие этапы, задачи, историю и чат; разработчик работает с подпроектами отдельно. Создание и подключение доступны из общей очереди и обзора проекта. Подробности — [docs/subprojects.md](docs/subprojects.md).

В левом нижнем углу кабинета находятся профили клиента, куратора и разработчика. Для добавления профиля нужны его почта и пароль; затем можно переключаться одним нажатием. На телефоне список открывается кнопкой внизу слева. Сессии хранятся на сервере, действуют до 7 дней после входа и переживают обновление Docker. «Выйти» завершает все добавленные профили на этом устройстве.

Светлая и тёмная темы выбираются в верхней панели. При первом посещении используется системная тема, явный выбор сохраняется для всех кабинетов и страницы оплаты и синхронизируется между вкладками.

## Обновление

После изменений: проверки → push в GitHub → обновление контейнера. На сервере:

```bash
git pull --ff-only
SOURCE_REVISION="$(git rev-parse HEAD)" docker compose up -d --build --wait
docker compose ps
```

Установочные скрипты и отдельная системная служба API не нужны. Обновление сохраняет `portal-data`; не удаляйте том при пересоздании. Подробности домена и перехода со старой публикации — в [docs/deployment.md](docs/deployment.md).

## Структура

```text
src/
├── app/                 # Маршруты Next.js; (marketing) отделён от кабинетов
├── components/          # Общие UI-компоненты и оформление сайта
├── features/
│   ├── home/            # Главная
│   ├── projects/        # Кейсы студии
│   ├── services/        # Услуги
│   ├── payments/        # Расчёты оплаты
│   └── portal/          # Кабинеты, модели и API-клиент
├── config/              # Контент студии и навигация
├── lib/                 # Общие функции
└── styles/              # Общие стили
server/                  # API, роли, SQLite, чаты, интеграции и выдача фронтенда
public/                  # Статические материалы
Dockerfile               # Сборка Next.js и минимальный runtime на Node.js 24
compose.yaml             # Один контейнер и постоянный том
deploy/nginx.conf        # HTTPS домена → контейнер
scripts/                 # Сборка и локальный preview
tests/                   # Модульные, браузерные и Docker-проверки
docs/                    # Архитектура, требования и эксплуатация
```

## Разработка и проверки

Node.js 24, npm 10+:

```bash
npm ci
npm run dev
```

Next.js в разработке передаёт `/api/portal/` на `127.0.0.1:3158`. Отдельный API для локальной разработки: `npm run portal:start`; его настройки берутся из `.env.portal`. Для работы всех частей вместе используйте Docker.

| Команда | Назначение |
| --- | --- |
| `npm run lint` | Правила Next.js, React и границы модулей |
| `npm run typecheck` | Типы фронтенда и сервера |
| `npm run build` | Статический экспорт Next.js в `dist/` |
| `npm test` | Экспорт, платежи, права, интеграции и сохранность данных |
| `npm run test:e2e` | Chromium, четыре размера экрана и сценарии ролей |
| `npm run test:runtime` | Общий HTTP-обработчик и перезапуск базы без Docker |
| `npm run test:container` | Запуск уже собранного образа `node-studio:ci` и проверка пересоздания |

GitHub Actions проверяет типы, тесты и браузер, собирает Docker-образ и запускает его. Проверяется настоящий вход и сохранение пароля/сессии после пересоздания контейнера. Доступ к Docker daemon требуется для запуска контейнерных проверок.
